# launcher-ios

The Fossify iOS ports bundled into one app ("Fossify"), with a port of [Fossify Launcher](https://github.com/FossifyOrg/Launcher) as its home screen: the bundled apps play the installed apps. Each app opens full screen with a home button on its main screen to return. vCards shared to the launcher open in Contacts' import dialog.

    idl build -c release     # -> build/release/FossifyLauncher.ipa (ad-hoc signed; re-sign to install)
    idl install "<device>" FossifyLauncher

Ported: paged home grid (rows/columns from settings, swipe or fling between pages, page indicator) with the dock row; long press an item for its menu (app info = the app's About, rename, remove; hide icon in the drawer; resize / reconfigure / remove for widgets), keep moving to drag it: across pages (hold at a side, extra page at the end), into the dock, onto another icon to make a folder; folders (open, rename, reorder, drag out, remove, 16 apps max); the app drawer (swipe up / fling, pull down at the top to close, search with "go" launching the first match, grid with fast scroller, long press to drag onto home); widgets list (long press on empty home > Widgets: the apps' own widgets by app, searchable; drag one onto the grid, its configure screen runs when placed, cancel removes it; resize frame like upstream); hidden icons screen; rename dialog; settings (customize colors, manage hidden icons, drawer column count / search bar / auto keyboard / close drawer on app open / labels, home rows / columns / labels, about); first run fills the dock like upstream (dialer, SMS, browser, store, camera -> Phone, Messages, Contacts, Gallery, Camera). Layout and hidden icons are JSON in Application Support/Launcher, settings `launcher_`-prefixed UserDefaults.

Differences forced by iOS: the launcher can't be the system home screen, list or uninstall other apps, read or set the system wallpaper, lock the screen or pin shortcuts, so: no uninstall / set as default / double tap to lock / app shortcuts; widgets are the bundled apps' SwiftUI widgets (`Model/WidgetRegistry.swift`), not other apps'; the background is the user's pick of the AOSP wallpapers in `Resources/Wallpapers.bundle` (Apache-2.0, see its NOTICE; "Android 14" by default), an image from Photos, or the theme background (labels then use the theme's text color instead of white); returning from an app (its home button) closes the drawers like upstream's home button.

Bundled: Calculator, Calendar, Camera, Clock, Contacts, Documents, File Manager, Gallery, Keyboard (also the system keyboard: Settings > General > Keyboard > Keyboards > Add New Keyboard > Fossify Keyboard; its settings / clipboard buttons open `fossify-keyboard://` in the launcher), Messages, Music Player, Notes, Paint, Phone, Thank You, Voice Recorder. Files shared to the launcher are routed by type (`BundledApp.handling`): vCards to Contacts, .ics to Calendar, text to Notes, documents to Documents, audio to Music Player, images to Paint, the rest to File Manager. Notifications go through commons' `NotificationHub` so Clock and Calendar don't replace each other's delegate.

Each app still builds on its own. Its repo splits into a static `<App>Kit` module (`Sources/`, public entry view `CalculatorRoot` / `ContactsRoot`) and a one-file app target (`App/main.swift`). The launcher links the kits and [commons-ios](https://github.com/jbisfun/commons-ios) from the sibling checkouts in `fossify-ios/` (calculator-ios, contacts-ios, commons-ios). An app hosted by the launcher gets `\.closeApp` in its environment and shows `CloseAppButton`. Launcher sources: `Sources/Model` (BundledApp, config, layout store, widget registry, wallpapers), `Sources/UI` (home screen, drawer, widgets list, menus, settings), `Sources/main.swift`.

Adding an app: give it the Kit/App split, add its Kit target to `idlproj.yml`, merge its Info.plist keys into the launcher's `info:`, add a case to `BundledApp` (`Model/BundledApp.swift`, and its file types to `handling`) and to `AppView` (`UI/LauncherView.swift`), plus its 180 px icon as `Resources/AppIcons/<name>.png`; its widgets (`<App>Widgets.all`) go into `widgetProviders`. Resources of a Kit (e.g. Calendar's `Holidays.bundle`, Camera's `CameraSounds.bundle`) must be copied into `Resources/`, since idl resources can't point outside the target dir.
