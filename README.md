# launcher-ios

The Fossify iOS ports bundled into one app ("Fossify"), with a port of [Fossify Launcher](https://github.com/FossifyOrg/Launcher) as its home screen: the bundled apps play the installed apps. Opened apps run in their own windows under an AOSP navigation bar and notification shade (SystemUI port). vCards shared to the launcher open in Contacts' import dialog.

    idl build -c release     # -> build/release/FossifyLauncher.ipa (ad-hoc signed; re-sign to install)
    idl install "<device>" FossifyLauncher

Ported: paged home grid (rows/columns from settings, swipe or fling between pages, page indicator) with the dock row; long press an item for its menu (app info = the app's About, rename, remove; hide icon in the drawer; resize / reconfigure / remove for widgets), keep moving to drag it: across pages (hold at a side, extra page at the end), into the dock, onto another icon to make a folder; folders (open, rename, reorder, drag out, remove, 16 apps max); the app drawer (swipe up / fling, pull down at the top to close, search with "go" launching the first match, grid with fast scroller, long press to drag onto home); widgets list (long press on empty home > Widgets: the apps' own widgets by app, searchable; drag one onto the grid, its configure screen runs when placed, cancel removes it; resize frame like upstream); hidden icons screen; rename dialog; settings (customize colors, manage hidden icons, drawer column count / search bar / auto keyboard / close drawer on app open / labels, home rows / columns / labels, wallpaper, system navigation, quick settings tiles, about); fling down on home opens the shade (expandNotificationsPanel); first run fills the dock like upstream (dialer, SMS, browser, store, camera -> Phone, Messages, Contacts, Gallery, Camera). Layout and hidden icons are JSON in Application Support/Launcher, settings `launcher_`-prefixed UserDefaults.

Differences forced by iOS: the launcher can't be the system home screen, list or uninstall other apps, read or set the system wallpaper, lock the screen or pin shortcuts, so: no uninstall / set as default / double tap to lock / app shortcuts; widgets are the bundled apps' SwiftUI widgets (`Model/WidgetRegistry.swift`), not other apps'; the background is the user's pick of the AOSP wallpapers in `Resources/Wallpapers.bundle` (Apache-2.0, see its NOTICE; "Android 14" by default), an image from Photos, or the theme background (labels then use the theme's text color instead of white); Home closes the drawers like upstream's home button.

SystemUI port (`Sources/System`): AOSP 3-button navigation bar (ic_sysbar_back/home/recent, 48dp bar, 70dp keys, light/dark icons over the content; apps and their full-height sheets are inset by it) or gesture navigation (handle: swipe up = home, swipe up and hold = overview, swipe in from either edge = back), picked in Settings > System navigation. Back hides the keyboard, cancels the topmost alert / dismisses the topmost sheet, pops the topmost navigation stack, runs the app's `onBackPressed` callbacks (commons `BackNavigation.swift`; Paint and Notes ask about unsaved changes there), else sends the app to the background; on home it clears the drawer search, closes drawers, the resize frame and the folder. Home closes everything back to the home screen. Overview: cards of up to 8 recent apps with their last snapshots, swipe sideways, swipe a card up to close it, tap to switch, "Clear all"; recent apps stay alive (their windows are only hidden). Notification shade from the top edge anywhere: header (clock, date, battery) + 2x2 quick tiles, pull again for the paged 2x4 tiles, brightness slider and footer (edit, settings); tiles: flashlight, dark theme, auto-rotate, keep screen on, record audio (Voice Recorder), alarm / timer (Clock), camera, calculator, with AOSP-style tile editing (drag to reorder, tap to add/remove, reset), Music Player media controls while a track is loaded, and the process' delivered notifications grouped by app (swipe to dismiss, tap to open the app, clear all). Launcher settings are registered with commons `SystemSettingsRegistry` (wallpaper, home screen, navigation mode, quick settings tiles, hidden apps, Fossify Keyboard settings, the bundled apps list) for the Settings app.

SystemUI differences forced by iOS: it only covers this app, so iOS' own status bar, home indicator gesture (deferred, second swipe still leaves), Control Center and keyboard stay above it; no Wi-Fi / Bluetooth / airplane / DND / location / cast tiles (apps can't toggle them); only this app's notifications are listed and a tap opens the owning app instead of running its notification handler; the navigation bar stays at the bottom in landscape and under the keyboard (no IME back key); Camera keeps only its snapshot in recents (its capture session can't run hidden) and restarts when reopened.

Bundled: Calculator, Calendar, Camera, Clock, Contacts, Documents, File Manager, Gallery, Keyboard (also the system keyboard: Settings > General > Keyboard > Keyboards > Add New Keyboard > Fossify Keyboard; its settings / clipboard buttons open `fossify-keyboard://` in the launcher), Messages, Music Player, Notes, Paint, Phone, Thank You, Voice Recorder. Files shared to the launcher are routed by type (`BundledApp.handling`): vCards to Contacts, .ics to Calendar, text to Notes, documents to Documents, audio to Music Player, images to Paint, the rest to File Manager. Notifications go through commons' `NotificationHub` so Clock and Calendar don't replace each other's delegate.

Each app still builds on its own. Its repo splits into a static `<App>Kit` module (`Sources/`, public entry view `CalculatorRoot` / `ContactsRoot`) and a one-file app target (`App/main.swift`). The launcher links the kits and [commons-ios](https://github.com/jbisfun/commons-ios) from the sibling checkouts in `fossify-ios/` (calculator-ios, contacts-ios, commons-ios). Hosted apps no longer get `\.closeApp` (so no `CloseAppButton`); they get `\.backPressedDispatcher` and `\.finishApp`. Launcher sources: `Sources/Model` (BundledApp, config, layout store, widget registry, wallpapers), `Sources/UI` (home screen, drawer, widgets list, menus, settings), `Sources/System` (task windows, navigation bar, recents, shade, quick settings, system settings registration), `Sources/main.swift`.

Adding an app: give it the Kit/App split, add its Kit target to `idlproj.yml`, merge its Info.plist keys into the launcher's `info:`, add a case to `BundledApp` (`Model/BundledApp.swift`, and its file types to `handling`) and to `AppView` (`UI/LauncherView.swift`; it then also appears in `SystemSettingsRegistry.apps`), plus its 180 px icon as `Resources/AppIcons/<name>.png`; its widgets (`<App>Widgets.all`) go into `widgetProviders`. Resources of a Kit (e.g. Calendar's `Holidays.bundle`, Camera's `CameraSounds.bundle`) must be copied into `Resources/`, since idl resources can't point outside the target dir.
